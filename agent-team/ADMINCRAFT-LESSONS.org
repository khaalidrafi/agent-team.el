* 1. BACKPORT INTO THE PROMPT LAW (AGENTS.md / COMMON.org / BOOTSTRAP.org)

** 1a. MEMBER ID FORMAT LAW (v2 — Owner refined it the same day)
   v1 (13:22Z): every member ID is PROVIDER/MODEL@PLATFORM.
   v2 (16:54Z, CORRECTION that supersedes the blanket rule):
   "PROVIDER/ should only be included with API models!" — key-served
   API lanes keep the prefix (zai/ groq/ openrouter/ gomodel/ ...,
   all on goose); platform-native bundled brains are BARE
   model@platform (qwen3.8-flash@qoder, deepseek-v4.1-flash@codebuddy,
   glm-5.3@codebuddy). Bare provider-less ids stay invalid for API
   lanes. One brain on two bodies = two members (body shapes output).

** 1b. ATOMIC RENAME LAW (the trap the format law creates)
   Renaming a member ID must change ALL of: TEAM-CONTROL.org #+TURN
   value, the workflow's turn-control case arm, and the advance arm —
   in ONE commit. Miss one and the rotation reads an unknown ID ->
   BLOCKED -> the chain stalls (unknown-refusal is correct behavior,
   see 2a; the rename discipline is what prevents triggering it).

** 1c. CONSULT LAW
   Every hire is posted to the Owner as a roles-with-members list
   BEFORE activation, and the list is re-shared after every staffing
   change. We hired first and consulted after — the Owner's rebuke
   ("You should have consulted me once hired") became chain law.

** 1d. HR LEDGER LAW (MEMBERS.org is a living HR file, not a roster dump)
   - HIRES WITH REASONS: each role justified by model capability,
     public benchmarks, hands-on reviews, AND observed CI performance.
   - PERFORMANCE REVIEWS at every pause window (see 2b): segments
     delivered, gate green first try, stalls, findings; verdicts
     KEEP / WATCH / PROBE / RELEASE (2 stalls no finding = WATCH, 3 =
     RELEASE — but root-cause the BODY before firing the BRAIN, see 5).
   - Record lane-vs-seat honestly: the result line names the lane that
     ACTUALLY ran; HR records the seat.

** 1e. SECRET LAW remains: env-var NAMES only, never values; secret-guard
   redaction at commit/ingest/artifact choke points. GitHub secret
   VALUES are write-only and cannot be copied cross-repo — keep
   STAGED NEEDS-KEY rows in the roster; each activates the moment its
   key lands in the repo.

* 2. BACKPORT INTO THE CI TEMPLATE (agent-team.yml)

** 2a. REAL ROTATION with unknown-refusal (we fixed a no-op pointer)
   The old pointer advanced cosmetically. Now: one case arm per seat
   in BOTH directions (turn-control maps pointer->seat; finalize maps
   seat->next-pointer), and an unknown pointer REFUSES (BLOCKED)
   instead of silently running the wrong lane. Keep legacy IDs as
   alias arms during migration.

** 2b. PAUSE-AFTER-TODO law (Owner-invented in admincraft, keep it)
   `#+PAUSE-AFTER-TODO: ON` + finalize greps the segment diff for
   `:DELIVERED:` on the board -> decision=paused-todo-review -> arms
   `#+CHAIN-PAUSE` -> next run mode=paused (halts cleanly, no burn) ->
   the LEAD reviews and clears the marker to resume. Effect: the Owner
   sees a report after every delivered TODO and no runaway burn. It
   also gives the HR review (1d) a natural cadence. Owner refinement
   2026-10-22 17:19Z: the pause is OPT-IN, not a mandate — DEFAULT
   OFF; chains run CONTINUOUSLY and may deliver MULTIPLE TODOs without
   halting; only an explicit Owner order arms #+PAUSE-AFTER-TODO: ON
   (a cadence the Owner chooses).

** 2c. EMPTY-SEGMENT law
   A lane exiting 0 with ZERO commits is NOT progress. Count post-turn
   commits as a first-class signal; N no-progress segments -> backoff
   (we use 4). This caught real failures AND exposed the codebuddy
   body bug (see 5).

** 2d. RACE-PROOF control commits
   The Lead's pushes or a concurrent finalize can move the base branch
   while a segment runs. Before the pointer sed: git fetch + reset
   --hard origin/<base> + re-apply; push with a 3x retry loop. We lost
   a rotation pointer to a silently-dead control push (run
   39485635406) and rebuilt this.

** 2e. FALLBACK CHAINS with honest result lines
   Every seat executes a fallback chain into PROVEN lanes (e.g.
   codebuddy -> qoder -> zai@goose -> minimax@goose). The result line
   MUST name the lane that ran. For paid lanes: if the paid attempt
   fails, the fallback runs but the result line SAYS "PAID LANE
   FAILED — burn did NOT happen". A paid visit is never faked.

** 2f. PROVIDER QUIRKS (we bled for each of these)
   - goose appends /v1/chat/completions to OPENAI_HOST -> use the
     HOST + OPENAI_BASE_PATH split (run 39752778724: doubled /v1 ->
     404 on EVERY call, chain stalled).
   - qoder: pin HOME to the launcher's dir; permission-mode
     accept_edits DENIES ALL Bash (git/pytest) -> bypassPermissions
     (run 39488529938 escalation).
   - `docker run -e NAME` (bare) passes EMPTY strings for vars the
     outer shell never exported (smoke test: SEAT=[]) — pass values
     explicitly: -e SEAT="${SEAT}".
   - Verify model ids against the CLI'S OWN --help before wiring
     (we npm-install @tencent-ai/codebuddy-code locally and read the
     supported list: deepseek-v4.1-flash, glm-5.3, kimi-k3,
     gpt-6-astra, gpt-5.6-*). Never guess a flag in CI.

** 2g. TELEGRAM MIRROR must be non-fatal
   The owner-locked bridge (TELEGRAM_OWNER_ID only) + verdict/chat
   mirror is gold, but its push raced healthy runs to "failure" —
   make every bridge failure a warning, never the job result.

** 2h. SESSION COLLECT/RESTORE per turn
   Container is --rm; tar the CLI session dirs each turn, scrub, upload
   (30d artifact), restore before the seat's next segment. This is how
   a seat resumes with context instead of starting blind.

* 3. BACKPORT INTO THE WORKFLOW DOCS (TEAMIFY.org / templates)

** 3a. VISITING MEMBER pattern (new — invented for expiring credits)
   Expiring paid credits (e.g. 250 CodeBuddy credits dying Oct 27) ->
   budget = total / remaining days, ONE visiting turn per day, OUTSIDE
   the standing rotation: the Lead points #+TURN at the visiting ID,
   its advance rejoins the rotation where it left. Keep a BURN LEDGER
   (date, member, segment, credits, note) in MEMBERS.org. If the
   platform publishes no balance endpoint (CodeBuddy does not —
   console-only), say so in the ledger and calibrate from the Owner's
   console readings; never invent endpoints.

** 3b. PROBE IS EVIDENCE OF THE RUNTIME, NEVER OF QUALITY
   A green probe row hires nobody. A body earns its seat by landing
   real work behind the landing gate. Today's proof: a quality-96 PAID
   brain (glm-5.3) ran OK and delivered an empty segment — model tier
   != delivery.

** 3c. LANDING GATE as the only quality floor
   pytest + checks inside the segment AND at merge. Red work never
   lands, whoever produced it. The gate is what makes free-tier
   benchmaxxing risk (deepseek-v4.1-flash is HN-flagged) survivable.

** 3d. GIT HYGIENE for every agent step
   A stale LOCAL ref named like a remote-tracking ref ("origin/ai/main"
   as a local branch) makes `git log origin/ai/main` AMBIGUOUS and can
   silently show a dead line of history (we hit this today and nearly
   built on a base without the team's files). Clone-time check:
   `git for-each-ref` for shadowing names; use explicit
   refs/remotes/origin/<branch> in scripts.

x1) all ended "run OK" with ZERO commits. Two different brains, same
body, same symptom -> suspect the BODY, not the brains. Candidate

advertises CODEBUDDY_IS_SANDBOX), missing git identity inside its
session, -y permission scope vs Bash/Edit tools, or the BRIEF not
reaching it as a work order. Session artifacts (30d) are uploaded per
turn — read one before firing the members. Until fixed, treat the
codebuddy lane as burn-only, not delivery-capable.
